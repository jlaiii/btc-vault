A custodial Bitcoin wallet you host yourself.

Users sign up with a username and password, get a real BIP84 deposit address with a QR code, receive and send BTC at the fee speed they choose, and see every confirmation. The operator gets holdings, the ledger, withdrawal approvals, an audit trail — and per-account security controls.

Flask + gunicorn PostgreSQL ledger embit signing Esplora chain data Docker Compose TOTP 2FA mainnet or testnet
This page is a static demo. Every balance, address, transaction and account below is invented and lives only in your browser. There is no backend, no signup, and no bitcoin — nothing here can receive or move funds. The real thing is a Flask + PostgreSQL service you run on your own server.

Account gates (Admin → Account controls)

  • Require 2FA — the account is blocked until it enrols, including sessions already open
  • Remove 2FA for a lost phone and lost backup codes
  • Require a new password — next request lands on the change page
  • Unlock a locked-out account, clear a stale negative-balance flag
  • Confirmed inline on the card: the button you press is the one that runs

Money handling, in one screen

A custodial balance is a ledger claim on coins sitting in one shared hot wallet. Everything here exists to keep that claim honest.

Integers only

Every amount is an integer number of satoshis. There is no float in the money path — not for fees, not for parsing, not for storage. USD is display only.

Nothing evaporates

Deleting an account sweeps its balance onto an admin account first; if the sweep fails the delete is abandoned. A negative balance transfers as debt rather than being silently zeroed.

Nothing double-credits

Chain credits are keyed on (txid, vout), and the wallet marks its own broadcasts before sending, so its change outputs can never be re-read as fresh deposits.

Nothing silent

A cross-network address is refused, a signature is re-verified against the exact bytes about to be broadcast, and a broadcast failure refunds and raises an alert instead of swallowing the error.

Run your own

One host, Docker, and a domain or IP with TLS. Testnet is the default — start there. 

# clone and bootstrap (writes .env, secrets/master.key, a recovery phrase file and an admin)
git clone https://github.com/jlaiii/btc-vault.git
cd btc-vault
./scripts/setup.sh

# bring it up
docker compose up -d --build

# is it ready for real money? PASS / REVIEW / NOT READY, exit code non-zero while blocked
docker compose exec web python -m app.cli preflight

# the suites that prove behaviour (they print pass/fail counts)
docker compose exec -T web python /app/scripts/verify_crypto.py
docker compose exec -T web python /app/scripts/mainnet_check.py
docker compose exec -T web python /app/scripts/check_admin_user_controls.py

Before mainnet

  • Write the 24-word recovery phrase on paper and delete the file
  • 2FA on the admin account, and change the setup password
  • Switch networks with cli launch-network — it is a data migration, not a config toggle
  • Check the legal side: custodying other people's bitcoin is money transmission in the US

Known limits (honest ones)

  • Single hot wallet — no cold storage or multisig
  • One gunicorn worker: simple, and fine for a small pilot, not for load
  • No self-service password reset (no email is collected at all)
  • An operator with database access can adjust a balance; the audit log is the control
